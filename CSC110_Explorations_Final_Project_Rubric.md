# CSC110 Explorations Path | Final Project Rubric

## Learning goals

Apply introductory Python to a problem or experience your team cares about. Design a program people can interact with, organize the code into functions and modules, and choose how to store and reuse its data. Work together to test, document, and demonstrate the program, then reflect individually on your contribution and what you learned.

## Points at a glance

| Component | Points |
|---|---:|
| User Experience & Functionality | 10 |
| Python Programming & Code Design | 10 |
| Reliability, Process & Deliverables | 10 |
| **Total** | **30** |

## 1. User Experience & Functionality · 10 points

| Criterion | Full-credit evidence | Points |
|---|---|---:|
| **1.1 Core functionality and scope** | The project fulfills its stated purpose and provides substantial functionality, approximately the scope of three homework assignments. Main features work correctly for typical use cases. The scope reflects the instructor-approved plan or agreed revisions. | 2 |
| **1.2 Significant user interaction** | Users make meaningful choices or supply input that affects the program. Controls and prompts are understandable, and the program provides clear feedback about the results of user actions. | 2 |
| **1.3 Rich, understandable display** | Graphics or thoughtfully formatted text and ASCII output convey rich feedback to the user. Information is readable and organized, and the presentation supports the project's purpose. | 2 |
| **1.4 Data storage and reuse** | The program stores data in a form appropriate to its intended future use. Storage choices support efficient retrieval, updating, and reuse at the scale of the project, without unnecessary duplication or recomputation. Data are retained for as long as the project needs them. | 2 |
| **1.5 Coherent experience** | Features fit together into a usable whole. Users can understand how to begin, navigate the main tasks, and finish or exit as appropriate. The project's interactions, content, and outputs support its purpose. | 2 |

## 2. Python Programming & Code Design · 10 points

| Criterion | Full-credit evidence | Points |
|---|---|---:|
| **2.1 Functions and modules** | Multiple functions have clear, focused responsibilities and are grouped into modules with related purposes. Parameters and return values are used appropriately, and unnecessary repetition is avoided. | 2 |
| **2.2 Core programming concepts** | Conditionals, loops, and containers are used correctly and meaningfully. Data types and operations fit the task, and the implementation demonstrates broad application of concepts covered in CSC110. | 2 |
| **2.3 Readability and organization** | Names are descriptive, formatting and indentation are consistent, and program logic is easy to follow. Code and files are organized so another CSC110 student could understand and modify the project. | 2 |
| **2.4 Comments, docstrings, and headers** | Every function has a useful docstring, every Python file has a header, and comments explain non-obvious choices or logic. Documentation accurately describes the code. Placeholder docstrings do not count. | 2 |
| **2.5 Sources and code understanding** | Copied code blocks have surrounding citation comments and references at the start of the file. Students can explain their own code and how imported code is used. Only student-written code and course tools can earn full credit. | 2 |

| Criterion | Full-credit evidence | Points |
|---|---|---:|

| **3.5 Individual reflection** | Each student independently submits a 1-2 page reflection describing specific contributions, the dated work record, collaboration, problems and learning, and advice for future groups. The reflection is specific and thoughtful rather than a general summary. | 2 |

## Applying the rubric

**Appropriate expectations.** Full credit is achievable with introductory Python. Graphics and rich formatted text are both acceptable. Advanced libraries, classes, and extra features do not automatically earn more credit.

**Team and individual evidence.** We will assess shared code and group deliverables at the team level. We will assess the individual reflection and each student's required participation individually. Your written comments and explanations will be used as context to help us understand the contributions of each team member. Equal commit counts are not required.

**Equivalent criteria and fair scoring.** Any alternatives to a stated requirement should be agreed upon between the team and the instructors in advance, and should assess a comparable learning goal. We will credit demonstrable work even if the program does not run, and will avoid repeatedly deducting for the same underlying defect.
